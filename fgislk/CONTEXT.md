# fgislk

## Назначение и границы

Загрузка в общую PostGIS данных ИС ФГИС ЛК (СПД): **кварталы** в `quarters`, **выделы** в `taxation_piece`, **лесосеки** в `clearcut` (семантика и контур). Не прикладной UI, не DDL.

## Требования

**Данные.** Пишет семантику слоёв и контур из карточки СПД: квартал/выдел — `isNeedArea=true`; лесосека — `checkCoordinate=true|false` (параметр обязателен). Нет контура у лесосеки — норма: семантика пишется, `geom`/`crs` не затираем. Если координаты запрошены (`checkCoordinate=true`) и СПД вернул ошибку — один повтор той же карточки с `checkCoordinate=false`. Карточка лесосеки — поля в корне (без `payload`); контур — GeoJSON `clearcutLocation`, `crs` = `srid_nsi`. Квартал/выдел: `geom` из `area.contours`, `crs` = `coordinateSystemCode`. `geom` как пришло — без `ST_Transform`, без фиксированного SRID, без перестановки осей (путаница `latitude`/`longitude` в СПД не чинится). При обновлении не трогает `semantic_id`. Нет контура в карточке — уже записанные `geom`/`crs` не затираем. Нет поля в карточке — уже записанную дату не затираем. У квартала нет `tractName` — не затираем `tract`. Upsert квартала не затирает `clearcut_polled_at` / `has_clearcuts`. Схему не меняет: Alembic не вызывать. Объект — **учётный номер ФГИС ЛК** (уникален в таблице); субъект — контур учёта. Upsert по `fgis_id`: есть запись — обновление (в том числе `subject`), нет — вставка; дублей номера нет.

**Календарь (МСК).** Все даты — московские. К СПД конец периода всегда сегодня: иначе вчерашние изменения в выборку не попадут. В журнале закрываем вчера: сегодняшний день ещё не закрыт. Следующий прогон снова захватывает вчера: за уже закрытый день ФГИС ещё может отдать обновления.

**Ежедневная загрузка.** Волнами по виду на всех субъектов: кварталы, затем лесосеки, затем выделы. Карточки кварталов/выделов всегда с `isNeedArea=true`. У кварталов и выделов своё окно: со дня после последнего успешного закрытия **этого** `data_kind` по сегодня; начало не позже вчера. Нет истории вида — с вчера по сегодня. Лесосеки: нет `changedOverPeriod`. Очередь: кварталы субъекта с `has_clearcuts`; раз в 10 дней — все кварталы субъекта по календарю 1С (день месяца 31 — без полного обхода; иначе слот по последней цифре дня: `1/11/21` → `01–10`, `2/12/22` → `11–20`, … `10/20/30` → `91–99`). Квартал с `clearcut_polled_at` = сегодня в очередь не берём. Успех по кварталу (список + все карточки, в т.ч. пустой список; нет контура — не сбой) ставит `clearcut_polled_at` = сегодня и `has_clearcuts`. Сбой списка или части карточек квартала — `log.warning`, водяной знак не ставим, прогон продолжается, в журнал и `/status.error` не пишем. Кварталы из только что прокачанного периода кварталов не подмешивать. Простой сервиса — догон непрокачанных дней (для лесосек — ежедневно `has_clearcuts` и полный слот по календарю), не полный аудит с 2023. Ручной `GET /sync?start=1` (`audit=0`) — тот же догон. Успех без окна периода СПД день не закрывает. Последняя запись журнала «ошибка» по виду — повторить этот день вида, даже если раньше был успех. Ошибка вида не отменяет следующие волны и остальных субъектов волны. `GET /sync?stop=1` отвечает сразу: рвёт живые curl и снимает прогоны с записи; текущая CPU-пачка карточек может ещё доиграть в фоне. HTTP `/health`/`/status` стопом не блокируются.

**Аудит.** Полный проход с 01.05.2023 (или с указанной даты) по сегодня. Порядок выбранных видов по всем субъектам: кварталы, лесосеки, выделы. Неотмеченный вид пропускаем. Флаги `quarters=` / `taxation_piece=` / `clearcut=` (`1` или `0`); все нули — отказ; без флагов — все три вида (как `GET /sync?audit=1`). Для лесосек период в СПД не уходит: отбор `clearcut_polled_at IS NULL OR < начало окна`; `clearcut_polled_at` = сегодня — не опрашивать. Флаг `area=` (`1` / `0`) только с `audit=1`: с координатами — `isNeedArea` (квартал/выдел) или `checkCoordinate` (лесосека); без флага или `0` — без контура, `geom`/`crs` не трогаем. `area=` с `start=1` игнорируется. К СПД по кварталам/выделам сначала весь период; пустой ответ — сдвиг начала на месяц при том же конце. Можно ограничить субъектами. Запуск: `GET /sync?audit=1`, дата — `day=`.

**Точечный опрос.** `GET /updateListCuttingAreaByQuarter?fgis_id={учётный номер квартала}` (алиас `quarter=`; старый `GET /sync?clearcut=1&quarter=`). Без `start`/`audit`/`stop`. Субъект — префикс номера; явный `subject=` должен совпасть. Квартала нет в `quarters` — 400. Вне очереди ежедневного слота: карточки без пропуска по `read_at`; `clearcut_polled_at` = сегодня не мешает. Координаты всегда. 202 в фоне; субъект уже в прогоне — 409.

**Повторное чтение карточек.** Карточку в СПД не запрашиваем, если её недавно уже читали (своя таблица вида), кроме точечного опроса:

- ежедневная загрузка — вчера или сегодня;
- аудит — за последние два дня (включая сегодня).

Запрашиваем новые учётные номера в списке и те, что читали раньше этого порога. После чтения в строке — дата чтения (`read_at`) = сегодня.

**Журнал** (`fgis_import_history`): субъект, закрываемый день, окно (`period_start`…`period_end`), результат, число обновлённых карточек (`updated_count`), вид данных (`quarters` / `taxation_piece` / `clearcut`). На успех и ежедневная загрузка, и аудит пишут: день = вчера, конец окна = сегодня. Для лесосек окно в журнале как у соседних видов, в СПД за период не ходим; `changed_total` — число кварталов в очереди. Ориентир следующего ежедневного прогона — по виду: максимальный закрытый день среди успехов с непустым окном; у старых аудитов, где день совпадал с концом окна, ориентир = этот день минус сутки. Аудит по ходу пишет пачки по 100 со статусом «частично» (`partial`: ориентир не двигает); в конце — успех. Ежедневная загрузка пишет успех и при нуле обновлений (лесосеки — если очередь кварталов обработана). Признак аудита без отдельной колонки: начало окна = 01.05.2023 или живой режим `audit`.

**Статус.** Срез по дате запроса (конец окна `period_end`, параметр `day=`, по умолчанию сегодня) — **одна строка на субъект и вид данных** с максимальным `updated_count`; `prev_day` / `next_day`. Отбор `subject=`, `data_kind=` (`quarters` / `taxation_piece` / `clearcut`). Живой прогон, если конец его окна совпадает со срезом: вместо журнала `in_progress`, `result=running`, `progress` = доля обработанного/`changed_total` (кварталы и выделы — карточки; лесосеки — пройденные кварталы очереди, не карточки; `updated_count` — карточки). Прошлый прогон того же вида — в `last`. Сбои чтения лесосек по кварталу в `error` и витрину admin не выводим. Точечный `GET /updateListCuttingAreaByQuarter`.

**Параллелизм и старт процесса.** `FGIS_MAX_WORKERS` (по умолчанию 5) — субъектов одного вида сразу; следующая волна после завершения вида. `FGIS_BATCH_WORKERS` (по умолчанию 3) — параллельных пачек карточек и пачек списков лесосек (`get-no-by-quarter`) внутри субъекта. Живых запросов к СПД на процесс = произведение. Пачка — одна сессия curl (`next`, reuse), не отдельный процесс на карточку или на список квартала. Кварталы и выделы: очередь воркеров (как лесосеки), не `gather` на все чанки; без контура HTTP-пачка = 100 (`FLUSH_BATCH`); с контуром (`need_area`) — 5 карточек в одном curl (`AREA_BATCH`), семантика в БД сразу, журнал `partial` по-прежнему каждые 100. Сброс семантики каждые 100 карточек (`FLUSH_BATCH`); по лесосекам пустые кварталы — водяной знак пачкой, с лесосеками — коммит и водяной знак после квартала. `/health`: версия + `alembic_revision`. На старте: `GET {MIGRATE_URL}/ready` и `REQUIRED_SCHEMA`; схема не та — не стартовать.

## Ограничения и допущения

- Импорт ограничен квотами ФГИС, не N реплик fgislk без координации.
- Год лесоустройства не маппим.
- HTTPS к порталу: `FGIS_TLS` в константах. Пусто — `schannel` на Windows, `openssl` на Linux. `schannel` — только **Windows** `curl.exe` **(Schannel)**; этот путь не менять. СПД `fgislk.gov.ru` на Linux без gost-engine даёт `error:0A000410`. `openssl` — системный `curl` с gost-engine (`GOST2012-GOST8912-GOST8912`, `OPENSSL_CONF`, `-k`); установка `sudo bash fgislk/install_gost_engine.sh`. Windows: `fgislk/run.ps1`.
- `FGIS_MAX_WORKERS`, `FGIS_BATCH_WORKERS`, `FGIS_TLS`, `FGIS_HOST`, логин и пароль — HTTP `constants`, не `.env`. Пул SQLAlchemy и кап HTTP к СПД с размера на старте не пересобираются.

## Интерфейсы

- **ИС ФГИС ЛК:** СПД `forestQuarter/changedOverPeriod` и `forestQuarter/{id}`; `taxationPiece/changedOverPeriod` и `taxationPiece/{id}` (`isNeedArea=true` на карточке, когда нужны координаты); список лесосек `clearcut/get-no-by-quarter/{учётный номер квартала}` (поле `clearcutNo` в корне; нет лесосек — `PIL_CLEARCUT0012` как пустой список); карточка `clearcut/{id}` (`checkCoordinate=true|false` обязателен, без параметра и `isNeedArea` — 500; ошибка при `true` — повтор с `false`; ответ без обёртки `payload`); заголовки `login` / `password` из констант. TLS — `FGIS_TLS`.
- **Postgres:** те же `POSTGRES_`*; запись в `quarters`, `taxation_piece`, `clearcut` и `fgis_import_history`.
- **migrate:** `/ready` и `REQUIRED_SCHEMA` перед стартом.
- **HTTP** (порт `FGISLK_PORT`, по умолчанию 8081): `/health`, `/ready`, `/status` (`day`, `subject`, `data_kind`). `GET /panel` — манифест для admin. `GET /history` — журнал (HTTP, не витрина; `data_kind=` опционален). Команды: `GET /sync?start=1`, `GET /sync?audit=1`, `GET /sync?audit=1&day=YYYY-MM-DD`, `GET /sync?audit=1&quarters=1&taxation_piece=0&clearcut=0`, `GET /sync?audit=1&area=1`, `GET /updateListCuttingAreaByQuarter?fgis_id=`, `GET /sync?clearcut=1&quarter=`, `GET /sync?stop=1`; субъекты — `subject=07` или `subject=07,16,21`. `stop` с `subject=` нельзя. `quarters=` / `taxation_piece=` / `clearcut=` / `area=` только с `audit=1` (`area=` на `start=1` игнорируется; точечный опрос — отдельный режим).
- **admin:** `/panel`, `/status`, команды через `/sync` и `/updateListCuttingAreaByQuarter`. Настройки — карточка constants. `/history` не показывает.
- **api:** тот же точечный опрос по `GET /updateListCuttingAreaByQuarter`.
- **constants:** `CONSTANTS_URL`, `GET /items/{key}` для прикладных ключей.
- **Потребители:** общая PostGIS, ключ связи — учётный номер ФГИС ЛК.

## Архитектура решения

ИС ФГИС ЛК → fgislk (`FGIS_TLS` из constants) → `quarters` / `taxation_piece` / `clearcut` + `fgis_import_history`. Модель слоя — [spatialData/CONTEXT.md](../spatialData/CONTEXT.md). Цикл после полуночи МСК и на старте; вручную: `start=1` / `audit=1` / `updateListCuttingAreaByQuarter` / `stop=1`. Advisory lock на субъект в Postgres (`fgislk:{subject}`) на время одного вида — отдельное соединение с ping; запись семантики из пула (`pool_pre_ping`), не через lock-сокет.
