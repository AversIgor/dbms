# fgislk

## Назначение и границы

Загрузка в общую PostGIS данных ИС ФГИС ЛК (СПД): **кварталы** в `quarters` и **выделы** в `taxation_piece`. Координаты не грузим. Не прикладной UI, не DDL. Лесосеки — позже.

## Требования

**Данные.** Пишет семантику слоёв. При обновлении из СПД не трогает `geom` и `semantic_id`. Схему не меняет: Alembic не вызывать. Нет поля в карточке — уже записанную дату не затираем. У квартала нет `tractName` — не затираем `tract`. Объект — **субъект** + **учётный номер ФГИС ЛК**.

**Календарь (МСК).** Все даты — московские. К СПД конец периода всегда сегодня: иначе вчерашние изменения в выборку не попадут. В журнале закрываем вчера: сегодняшний день ещё не закрыт. Следующий прогон снова захватывает вчера: за уже закрытый день ФГИС ещё может отдать обновления.

**Ежедневная загрузка.** На субъект сначала кварталы, потом выделы. У каждого вида своё окно: со дня после последнего успешного закрытия **этого** `data_kind` по сегодня; начало не позже вчера. Нет истории вида — с вчера по сегодня. Простой сервиса — догон непрокачанных дней, не полный аудит с 2023. Ручной `GET /sync?start=1` (`audit=0`) — тот же догон. Успех без окна периода СПД день не закрывает. Последняя запись журнала «ошибка» по виду — повторить этот день вида, даже если раньше был успех. Ошибка кварталов не отменяет выделы. `GET /sync?stop=1` останавливает все текущие прогоны раздела.

**Аудит.** Полный проход с 01.05.2023 (или с указанной даты) по сегодня. Порядок выбранных видов: кварталы, затем выделы. Неотмеченный вид пропускаем. Флаги `quarters=` / `taxation_piece=` (`1` или `0`); оба нуля — отказ; без флагов — оба вида (как `GET /sync?audit=1`). К СПД сначала весь период; пустой ответ — сдвиг начала на месяц при том же конце, пока не появятся данные или начало не уйдёт за сегодня. Можно ограничить субъектами. Запуск: `GET /sync?audit=1`, дата — `day=`.

**Повторное чтение карточек.** Карточку в СПД не запрашиваем, если её недавно уже читали (своя таблица вида):

- ежедневная загрузка — вчера или сегодня;
- аудит — за последние два дня (включая сегодня).

Запрашиваем новые учётные номера в списке за период и те, что читали раньше этого порога. После чтения в строке — дата чтения (`read_at`) = сегодня.

**Журнал** (`fgis_import_history`): субъект, закрываемый день, окно СПД (`period_start`…`period_end`), результат, число обновлённых карточек (`updated_count`), вид данных (`quarters` — кварталы, `taxation_piece` — выделы). На успех и ежедневная загрузка, и аудит пишут: день = вчера, конец окна = сегодня. Ориентир следующего ежедневного прогона — по виду: максимальный закрытый день среди успехов с непустым окном; у старых аудитов, где день совпадал с концом окна, ориентир = этот день минус сутки. Аудит по ходу пишет пачки по 100 со статусом «частично» (`partial`: ориентир не двигает); в конце — успех. Ежедневная загрузка пишет успех и при нуле обновлений. Признак аудита без отдельной колонки: начало окна = 01.05.2023 или живой режим `audit`.

**Статус.** Срез по дате запроса (конец окна `period_end`, параметр `day=`, по умолчанию сегодня) — **одна строка на субъект и вид данных** с максимальным `updated_count`; `prev_day` / `next_day`. Отбор `subject=`, `data_kind=` (`quarters` / `taxation_piece`). Живой прогон, если конец его окна совпадает со срезом: вместо журнала `in_progress`, `result=running`, `progress` = доля `updated_count`/`changed_total`. Прошлый прогон того же вида — в `last`.

**Параллелизм и старт процесса.** `FGIS_MAX_WORKERS` (по умолчанию 5) — субъектов сразу, одна задача на субъект (внутри — кварталы, затем выделы). `FGIS_BATCH_WORKERS` (по умолчанию 3) — параллельных пачек карточек внутри субъекта. Живых запросов к СПД на процесс = произведение. Пачка — одна сессия curl (`next`, reuse), не отдельный процесс на карточку. Сброс семантики каждые 100 карточек (`FLUSH_BATCH`). `/health`: версия + `alembic_revision`. На старте: `GET {MIGRATE_URL}/ready` и `REQUIRED_SCHEMA`; схема не та — не стартовать.

## Ограничения и допущения

- Импорт ограничен квотами ФГИС, не N реплик fgislk без координации.
- Год лесоустройства не маппим.
- HTTPS к порталу: `FGIS_TLS` в `.env`. Пусто — `schannel` на Windows, `openssl` на Linux. `schannel` — только **Windows** `curl.exe` **(Schannel)**; этот путь не менять. СПД `fgislk.gov.ru` на Linux без gost-engine даёт `error:0A000410`. `openssl` — системный `curl` с gost-engine (`GOST2012-GOST8912-GOST8912`, `OPENSSL_CONF`, `-k`); установка `sudo bash fgislk/install_gost_engine.sh`. Windows: `fgislk/run.ps1`.
- Allowlist (`FGIS_MAX_WORKERS`, `FGIS_BATCH_WORKERS`, `FGIS_TLS`, `FGIS_HOST`) меняется через `PUT /settings`: overlay-файл (`FGISLK_SETTINGS_FILE`, иначе `fgislk-settings.json` в cwd) поверх `.env`. Пул SQLAlchemy и кап HTTP к СПД с размера на старте не пересобираются. Рестарт без файла возвращает значения `.env`. Секреты и `POSTGRES_*` через API нельзя.

## Интерфейсы

- **ИС ФГИС ЛК:** СПД `forestQuarter/changedOverPeriod` и `forestQuarter/{id}`; `taxationPiece/changedOverPeriod` и `taxationPiece/{id}`; заголовки `login` / `password` из `.env`. TLS — `FGIS_TLS`.
- **Postgres:** те же `POSTGRES_`*; запись в `quarters`, `taxation_piece` и `fgis_import_history`.
- **migrate:** `/ready` и `REQUIRED_SCHEMA` перед стартом.
- **HTTP** (порт `FGISLK_PORT`, по умолчанию 8081): `/health`, `/ready`, `/status` (`day`, `subject`, `data_kind`). `GET /panel` — манифест для admin. `GET /history` — журнал (HTTP, не витрина; `data_kind=` опционален). `GET`/`PUT /settings` — allowlist. Команды: `GET /sync?start=1`, `GET /sync?audit=1`, `GET /sync?audit=1&day=YYYY-MM-DD`, `GET /sync?audit=1&quarters=1&taxation_piece=0`, `GET /sync?stop=1`; субъекты — `subject=07` или `subject=07,16,21`. `stop` с `subject=` нельзя. `quarters=` / `taxation_piece=` только с `audit=1`.
- **admin:** `/panel`, `/status`, команды через `/sync`. Форму `/settings` и `/history` не показывает.
- **Потребители:** общая PostGIS, ключ связи — субъект + учётный номер ФГИС ЛК.

## Архитектура решения

ИС ФГИС ЛК → fgislk (`FGIS_TLS`) → `quarters` / `taxation_piece` + `fgis_import_history`. Модель слоя — [spatialData/CONTEXT.md](../spatialData/CONTEXT.md). Цикл после полуночи МСК и на старте; вручную: `start=1` / `audit=1` / `stop=1`. Advisory lock на субъект в Postgres (`fgislk:{subject}`).
