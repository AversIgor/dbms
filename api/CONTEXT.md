# api

## Назначение и границы

HTTP для форм, журнала и точечных эндпоинтов карты. Не мигратор схемы, не fgislk.

## Требования

- На старте: схема готова (`/ready` migrate) и свой `REQUIRED_SCHEMA`; mismatch — отказ стартовать. Alembic не вызывать.
- `/health`: версия приложения + `alembic_revision`.
- Связь с пространственными объектами — **субъект** + **учётный номер ФГИС ЛК** (см. [`spatialData/CONTEXT.md`](../spatialData/CONTEXT.md)).

## Ограничения и допущения

- Очередь отправки — таблицы Postgres (`exchanges`), не Kafka/Redis.
- XML/PDF/СМЭВ — другие процессы.
- Карта: точечные выборки — этот API.

## Интерфейсы

- **Клиенты:** `web` (HTTP), не Postgres напрямую.
- **Postgres:** те же `POSTGRES_*`, драйвер asyncpg.
- **migrate:** `GET {MIGRATE_URL}/ready` перед стартом.
- **fgislk / PostGIS:** чтение таблиц Spatial data по субъекту и учётному номеру ФГИС ЛК.

## Архитектура решения

`web` → HTTP `api` → PostGIS. Справочники — поиск по строке. Карта — точечные эндпоинты здесь.
